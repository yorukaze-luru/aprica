# アプリカ (Aprica)

ウェブサイトを、本物の Android アプリ (APK) に変換するジェネレーターアプリです。

「使いやすいのに、インストールできるアプリがなくてショートカットしか作れない」ウェブサイトを、
スマホの中で独立したアプリとして生成します。生成されたアプリはアプリ一覧に表示され、
全画面の WebView でサイトを開きます。

## ダウンロード

[Releases](https://github.com/yorukaze-luru/aprica/releases) から `aprica-vX.Y.apk` をダウンロードしてインストールしてください。

- 初回は Android の設定で「不明なアプリのインストール」の許可が必要です
- Google Play での配布はしていません

## 使い方

1. アプリカを開く
2. アプリ化したいサイトの URL とアプリ名を入力（パッケージ名は自動で提案されます）
3. アイコンを選ぶ（サイトのアイコンを自動取得 / 画像から選択 / 頭文字アイコンの自動生成）
4. 必要なら権限を ON にする（マイク / カメラ / 位置情報 / 通知。デフォルトは全て OFF）
5. 「APK を生成」→「インストール」

## 特徴

- 生成はすべて端末の中で完結します（サーバーに URL を送りません）
- 外部認証（OAuth など）でも、認証フローがアプリの中で完結しログインできます
- 生成時に選んだ権限だけがアプリに入ります（OFF の権限は APK から取り除かれます）
- ファイルのアップロード、サイト内でのマイク / カメラ / 位置情報の利用に対応
- アプリカ本体の新バージョンは GitHub Releases でチェックできます
  （更新チェック先はアプリに組み込み済み。設定ページの「更新を確認」ボタン）
- 設定ページ（右上の「☰ 設定」）で、権限トグルのデフォルト値を決められます
- 生成されるアプリには、読み込み表示（スプラッシュ／プログレスバー）と、
  通信エラー時の再読み込み画面が付きます

## プッシュ対応版（Pアプリカ）

サイトの Web プッシュ通知を受け取りたい人向けに、プッシュ対応版「Pアプリカ」もあります（v1.0.0 までは「アプリカ Push」という名前でした。v2.0.0 で「Pアプリカ」に改名しましたが、パッケージ名とアセット名は変わらないため、そのまま上書き更新できます）。

- 通常版の WebView エンジンではサイトのプッシュ通知が使えないため、プッシュ対応版は GeckoView（Firefox 系）エンジンのテンプレートを内蔵し、サイトの Web Push を UnifiedPush 経由で受け取れるようにした別エディションです
- ダウンロードは Releases から別アセット `aprica-push-vX.Y.Z.apk`（タグは `push-vX.Y.Z`）です。通常版の `aprica-vX.Y.Z.apk` とは別のリリース／アセットとして公開します
- 生成されるアプリ 1 つあたりのサイズは約 94MB です（GeckoView エンジン一式を含むため、通常版の生成アプリより大幅に大きくなります）。プッシュ対応版の本体 APK も約 95MB です
- **Pアプリカ自身が UnifiedPush の配信機能を内蔵しているため、配信アプリ（ntfy など）を別途インストールする必要はなくなりました。** ntfy などの配信アプリも引き続き使えます（後述の「Pアプリカ経由」で、Pアプリカの配信が OFF の場合や Pアプリカが無い場合は、端末にある他の配信アプリが使われます）。配信手段が何も無い場合でも、生成したアプリは通常通りサイトを閲覧できますが、サイトはプッシュを配送できません（購読が失敗します）
- Pアプリカの配信が動いている間は、常駐通知が 1 件だけ表示されます（プッシュの受信待機中であることを示すものです）。設定ページで配信を OFF にすることもでき、現在の配信状態も設定ページで確認できます
- 生成できるアプリの数には上限があります（生成アプリ 1 つが約 94MB と大きいためです）。デフォルトは 10 件で、設定ページで変更できます
- 通常版と同時にインストールして使い分けできます（別パッケージ `app.webgen.generator.push`）。ただし、生成履歴と端末内の署名キーは通常版とは別々になります。そのため、版をまたいで生成アプリを移す場合は、アンインストールしてから入れ直す必要があります（ログイン状態などのアプリ内データは引き継げません）
- プッシュ対応版で生成するときは、パッケージ名の自動提案の末尾に `.push` が付きます（通常版で生成した同名アプリと衝突しないようにするためです）

### 配信方式（生成時に選べます）

プッシュの届け方は、アプリを生成するときに 2 つから選べます。

- **Pアプリカ経由（推奨）**: プッシュの受信を Pアプリカがまとめて担当します。常駐通知は Pアプリカの 1 件だけで済みます。その代わり、Pアプリカがインストールされていて、配信が ON になっている必要があります
- **アプリ内蔵**: 生成したアプリ自身が配信機能を持ち、Pアプリカが無くても単体でプッシュを受け取れます。その代わり、生成アプリごとに常駐通知が 1 件ずつ表示され、接続もアプリごとに維持します

## 仕組み

- 内蔵の WebView テンプレート APK をベースに、URL・アプリ名・パッケージ名・アイコンを
  書き換えて再署名することで、サイトごとの独立アプリを生成します
  （バイナリ XML の文字列プール再構築による書き換え）
- 生成アプリの署名キーは初回起動時に端末内で作られ、端末内にのみ保存されます
- 署名キーはこのリポジトリには含まれていません

## 制限事項

- サイト側のプッシュ通知は Android WebView が対応していないため使用できません
  （通知権限はアプリ側のお知らせ専用です）
- Google ログインなど、提供側のポリシーで WebView 内ログインを禁止している
  認証方式は利用できない場合があります
- アプリカをアンインストールしたりデータを削除すると端末内の署名キーが失われ、
  以前に生成したアプリへ上書き更新できなくなります（再インストールが必要）

## ソースからビルドする場合

- 必要なもの: JDK 17、Android SDK (platform 34 / build-tools 34)、Kotlin コンパイラ
- `build_template.sh` でテンプレート APK を、`build_generator.sh` でアプリカ本体を
  ビルドします（Gradle デーモンを使わない手動パイプラインです）
- 署名キーとパスワードは各自で用意してください。パスワードは環境変数
  `WEB2APK_KS_PASS` で渡します（スクリプト内のデフォルト値はダミーです）
- このリポジトリのスナップショットには、バイナリ素材（ランチャーアイコン PNG、
  `generator-app/libs/apksig-only.jar`、生成済み `template.apk` アセット）は
  含まれていません。これらはビルド時の成果物・依存物です
  （apksig は Android SDK の apksigner から抽出。ライセンスは
  `generator-app/libs/NOTICE-apksig.txt` を参照）
